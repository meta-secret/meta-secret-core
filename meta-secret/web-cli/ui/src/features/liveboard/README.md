# Liveboard controller boundaries

Core supplies exact identities, canonical outcomes, eligibility and material readiness.
Presentation controllers render those instructions through injected ports; they do not
infer authority from device counts, names, disappearance or a queued/Unknown receipt.
Controller unit/composition checks are distinct from real application/session/route
integration. Its final validation remains a separate workflow gate.

## Fresh operation presentation and notification availability

The metadata-only observed operation Map is shallow-reactive. Both its first key
and an exact existing row replacement invalidate the actual parent/router computed
presentation without another read, event or Show. Values remain copied Core metadata;
publication order, selection, producer lifetimes, consumed/unread and R/U ownership
are unchanged. The existing exact current Remove correlation remains independent.

Waiting request paths use canonical eligible peers. A proven accepted/declined
response instead uses only its actual responder as a display endpoint, excluding
self. Unknown provenance and missing anchors create no returning packet. These
RequestVisual peers are never the Core eligible approver set or decision authority;
Core permissions and existing Done/completed visual retirement remain unchanged.

Home passes the current parent session ready flag through required notificationsReady
and ready props. Native Open and decisions require that flag plus their existing
pending and exact item permission guards. Unrelated pending Device work is not an
availability proxy. Error Dismiss stays clickable even unready/busy and requests only
the existing manual parent read path. No automatic clear, Open, auth or decision is added.

## Exact terminal mutation settlement

`createSecretController` exposes:

```ts
settleMutation({ passId, kind, preserveRecovered = false }): void
```

This pure method has no request or generation authority. It returns without effects
when disposed, when the exact card is absent, or when that Pass has no matching current
mutation. Otherwise it deletes only that Pass's mutation and owner, then calls the
existing `mask(passId)`. Masking advances that card's revision, clears held plaintext,
Copy and conceal state, and derives phase from the actual current descriptor. Other
cards, pending/Unknown owners, global lifetime, query and scroll remain unchanged.

The sole production caller belongs in the NEW `controller.ts` composition. Before
calling, it must match the current parent session/generation, locally admitted exact
Pass and kind, and the actual operation identity after snapshot reconciliation.
Delete requires exact canonical **Declined**, using the actual request UUID learned
from the retained SAME producer R/U source/reference. Recover uses its actual returned
Claim ID, matching the canonical Pass and requester/current device. It permits either
exact canonical **Declined**, or Core **Done** together with that same current Secret's
Core-ready primary `recover` under a ready member projection. Done alone, including
an inactive operation's readiness, cannot substitute for the current Secret instruction.
An absent/Unknown identity, pending/accepted approval alone, receipt phase, names,
counts or disappearance does not authorize settlement. Observation never submits or
continues a command, invokes Show, fabricates readiness or consumes unread.

An unambiguous canonical Remove may drive passive device presentation only when
there is no outstanding local pending owner or checked producer. A local intent
before its receipt, or an active producer without a UUID, cannot resolve through
that fallback. Only observation of the original R/U supplies its correlation.

The caller consumes that terminal correlation once. Re-reading an old terminal result
must not settle a later retry, and old session/generation callbacks must not settle a
new owner. The pure method alone cannot distinguish successive same-Pass/kind attempts:
a repeat is inert only while no new matching mutation exists. It supplies no new
eligibility, synthetic descriptor transition, approval, auth or Core business rule.
The optional presentation-only preservation is used only while the parent owns an
unfinished explicit recovered Show. It clears the completed mutation and every held
value/Copy/motion while retaining that exact unpublished local owner, not its old
render fence or a finished reveal. The guarded handoff below supplies fresh proof.

A genuinely new checked Delete producer admission supersedes only previously captured
terminal Delete display for the same exact Pass and current canonical requester.
This updates the Home visual immediately, including when UUID observation is still
pending. Canonical history and previous terminal markers remain intact; an Unknown
producer retains its original R/U ownership and cannot be unlocked by the old outcome.
Admitted source IDs are remembered until the existing session clear, so a repeated
receipt is never treated as new admission after its active entry settles. Cancelled,
rejected or pre-admission actions do not acknowledge old display, and Recover unread
metadata is not consumed by Delete.

Done observed elsewhere preserves exact unread metadata without marking it read.
Recovery Core Done stops the Home Vault request/reply animation: it proves actual requester
retrieval and explicit completion, and Core no longer permits Show of that old Claim.
Preserved unread metadata does not require endless network animation after Done.
While Core still supplies an eligible accepted Claim, only deliberate visible Show
of that exact Claim consumes its unread. Showing a new Claim cannot acknowledge an
old Done Claim. A later Recover remains an explicit eligible user action; no automatic
Show, request, auth or unread-read marker is added.
Pure, composition and parent-session tests measure separate scopes; this document
does not establish build or real-Core UI E2E acceptance. The final parent/session/routes
boundary documentation and other Required integration documentation remain pending.

## Exact Remove display and local ownership

Remove display uses the current snapshot row for an already observed exact kind/UUID,
with the remembered immutable requester and target. Contradictory replacements are
unusable, including after repeated ready reads. A small reactive Remove-key index
invalidates presentation when a new real key is first observed; it supplies no outcome,
producer correlation or permission. Other operation history/selection is unchanged.

Actual Applied Decline is done/done and remains a red response, unlike completed
Accepted Remove. Proven response endpoints come from the actual canonical/verified
responder even when terminal eligible peers are empty. Local2-to-1 uses the actual
requester response without a fictional remote packet. Accepted application is green;
current ready exact Accepted Done retires only that display monotonically. The current
two-device Vault then has no old request, Time Machine, Current or Remove controls.

Current acknowledges a Decline only after the same enabled preview really clears,
with current ready/session/identity checks after the action. A genuinely new checked
admission may supersede only its pre-captured exact same-target own terminal display,
including during a synchronization barrier. Cancellation, rejection, old source reuse,
unproven/foreign metadata or a terminal learned after intent cannot acknowledge it.
Visual consumption preserves canonical history, prior terminal markers and Recovery
unread; it never settles a producer, supplies a UUID or releases R/U ownership.

The pure device controller exposes only a readonly local hasPending boolean from its
actual private pending target. Busy/preview or a passive canonical phase is not local
ownership. While pending, target/forecast disappearance and blocked/absent/unproven
terminal data retain its guard and preview. Only a CURRENT usable-ready exact originally
bound UUID/requester/target and proven resolving response may release it. Blocked
responses can be drawn without releasing controls; passive canonical Waiting/Settling
continues to block its own controls across repeated reads without a local producer.

The active Remove correlation descriptor is retained until that fresh proven Decline
or accepted done/settled result. Existing read-only observation continues on the SAME
original R through invalid or absent metadata, so later valid proof can resolve it.
The composition captures the descriptor before retirement and re-reconciles devices
after the already existing observation learns a UUID, without an extra SDK call,
sync, continuation or write. The separate SDK registry still retains the original
receipt entry; its known-UUID per-subject lock key may disappear for an unproven
terminal under existing behavior. This UI repair does not harden or claim to retain
that registry key. Pending UI ownership and descriptor retention remain independent
of that registry, whose code and R/U sources are unchanged.

## Manual errors and parent read ownership

Every explicit controller error report is a new synchronous privacy event, including
the same sanitized message while tile04 still shows the previous error. A structural
setter scope restored in finally suppresses only duplicate handling by the synchronous
notification watcher; direct internal notification error writes still use that watcher.
The current parent's void hook revokes unfinished recovered capsules and latches its
existing required barrier. All held values, Copy and motion are cleared; authored Create
input closes but remains in its SAME transient owner for deliberate reopen.
Error text is neither an event identifier nor a readiness or permission proof.

The metadata-only sessionError bridge binds the emitting controller to the current
eligible parent and captures the current revision per invocation, including after key
replacement. Retired/reset/disposed owners cannot invalidate a successor. The bridge
contains no values, Claim handles, new counter, lane, stream or readiness policy.

Tile04 errors stay visible until their manual tap. Dismissal clears display only, checks
the same current owner after reactive effects and requests the existing serialized
required sync/read. Hidden/offline work remains latched for normal eligible resume.
Only current successful sync_now then get_state can satisfy the parent target; dismissal,
cache reads, elapsed time and older in-flight work cannot. A failure remains blocked
with a new sanitized manual error. No automatic retry or error auto-clear is added.
Ordinary genuine sync may restore technical readiness while an earlier04 error remains.

Fresh readiness never restores prior values/Copy/motion, consumes unread Recovery
or retries Show/auth/Copy/business commands. Typed FIFO/count, exact decision identity,
pending Unknown and original R/U ownership remain independent of this display/read
path. The user explicitly reopens the retained queue and authenticates its exact head.
Existing auth/key/manager/generation/member/reset/disposal guards fence late reads.

## Real routes and parent lifetime

The stable `VaultView` parent creates one `useVaultSession` and provides it through
`routeContext.ts`. Its child routes are `/` (Home), `/secrets` and `/profile`;
`/devices` redirects to the Home intent. Existing information, settings, tools and
contact records retain their own surfaces. Accepted components own the actual
RouterLink anchors, native Back/Forward and modifier/new-tab behavior; no document
click interception or full-page navigation is introduced.

The route context exposes a computed read of `session.controller`. Confirmed local
Reset may replace that controller, so children and dialogs must not capture its
getter result once in setup. They do not initialize a manager, create another SSE,
access a raw WASM wrapper or own an independent business executor. Global PasskeyAuth
and Toaster remain in App. The legacy NavBar is hidden only for the approved member
routes and the existing registration surface. Legacy Vault/Secrets/Devices renderers
are not mounted by those routes; their source is retained pending the separate caller
and legacy-resource retirement audit.

Authenticated first initialization uses the existing Skeleton presentation. Current
nonmember state enters Orbit registration; its ready event retains final-sync gating.
Canonical membership loss returns to Orbit. Subsequent required-sync blocking keeps
the member surface and safe metadata instead of hiding it behind a fullscreen loader.
All errors and incoming requests belong to Home tile04. On Secrets/Profile, an error
masks/blocks actions and remains retained for Back to Home; it does not navigate away,
add another notification tile or replace the current list/page.

## Writes, synchronization and transient data

Recover, Delete, incoming Approve/Decline, Remove and Create submit through the
existing controller ports. After awaiting a write intent, the route context asks the
same parent for a required serialized refresh only while the same controller and
parent identity remain current. OS confirmation on both decision branches stays in
the existing adapter/auth boundary. Show, Hide, Copy, preview and error dismissal do
not trigger this write refresh. Deletion remains on the current list route.

The parent/session and existing AppState lane own initialization, key/manager epochs,
the single authenticated SSE, online/page lifecycle and serialized sync/read. The
invalidation hook blocks readiness synchronously before debounce. A required-sync
failure stays blocked across cached reads and error dismissal; current successful
required sync/read is needed to satisfy that barrier. The route layer neither clears
the barrier nor calls manager.sync_now/get_state directly.

Query, scroll metadata, pending/Unknown ownership and unread belong to the shared
controller across child navigation. SecretsPage owns its scroll container restoration;
the route saves its emitted scroll and never queries internal DOM or uses KeepAlive.
The separately owned component seams provide that restoration and a Home canCreate
disabled binding; their tests/review remain separate from this source-only route work.

Plaintext, Copy callbacks and numeric motion state are synchronously invalidated by
the existing session/controller on route/filter exit, sync/error, auth/member/reset,
pagehide, tombstone and disposal. Create draft data belongs only to its transient
form, including inactive Plain value, mode/count and all24 Seed words. Ordinary SAME-session
sync/SSE/ready=false preserves OPEN/CLOSED and full input; it blocks submission and late
clipboard without closing. Error closes(clear:false), pins04 and retains SAME input for
deliberate reopen; route conceal also closes/preserves. Actual background/key/member/
identity/Reset/disposal and idle Cancel hard-clear every field. Hard view conceal retains
the original pending/Unknown latch; genuine owner change remains distinct. No automatic
reopen, retry, reveal, navigation or Web Create auth is inferred. Only exact canonical
ID/material readiness confirms creation, including clearing its original closed form.

Create has a private parent nesting fence before observable error/sync/projection effects,
so inline read-only observers cannot issue a write. Each new write owns its ticket before
port entry and clears the previous receipt; reconcile rechecks exact receipt+ticket+ID.
Private terminal consumption occurs before inner observers. Edit/paste/open revision is
separate from admitted-result lifetime; soft changes keep SAME inner rather than copying
input or disposing its pending receipt. Postcallback lifetime/edit/phase guards suppress old
errors after a new submit/disposal/owner change. These extra callback properties are also
source-reviewed, beyond the two direct ownership regressions.

## First recovered Show delivery

`recoveredReveal.ts` coordinates only the unfinished first delivery of one deliberate,
visible Show. The pure controller creates a nonserializable owner for the exact Pass,
Claim, card incarnation and current presentation. Its synchronous revoke listener
clears the helper's private raw capsule at route/filter exit, explicit Hide, modal/
Create conceal, page/offline boundaries, auth/key/manager/member/reset change, error,
tombstone or disposal. Late values are discarded; no readiness callback rearms it.
Every sync still immediately masks all already-held card values, Copy and motion.

While this owner remains unfinished, the parent's expected sync blocks may retain
only its pending metadata and private raw capsule. Parent material reconciliation
uses this explicit suspension path and checks SAME-Pass history on every published
projection. The baseline includes the exact accepted Claim and all retained relevant
canonical rows. Only that own accepted→Done progression is allowed; newly observed
Recover identities, accepted Delete/recreation, missing/changed history, changed
requester/responder/provenance or unexpected Secret instruction permanently revoke.
No count, name, opaque-ID ordering or wall clock supplies continuity or permission.

The adapter keeps the exact owned Claim through one borrowed `show_recovered` await
and frees it once. Returned text alone is not a server acknowledgement. It is held
only in the helper capsule, without decode, DOM/ref/Pinia/storage/log/URL/canvas
exposure. After that one return the same SSE owner synchronously retires its old
generation and opens a fresh authenticated subscription. `restartReady` resolves on
the actual successful HTTP response with body, after server subscribe; there is no
initial ready frame or replay. Old frames/errors remain generation/abort fenced.

Before retiring the current subscription, the parent synchronously latches its
required barrier and conceals ALL held plaintext/Copy/motion. Only the explicit
restart's first bootstrap read is subsumed. A separate metadata-only gap branch owns
the post-HTTP physical read independently of the pending value owner: filtering out
Show A cannot abandon the read or leave already-held B visible. After HTTP readiness,
it unconditionally advances a NEW parent required target and queues a fresh sync/read
through the existing single Store lane, behind any earlier flight. A pre-ready or
coalesced read cannot satisfy that target. Only after this parent obligation settles
does the handoff check its separate owner for delivery. The gap branch has no Pending,
card, raw-value capsule or delivery callback and never restores a cancelled value.

Parent identity/key/manager/generation/revision, active eligibility and current lease
are checked at every await and again after reactive blocking before subsequent work.
Route/filter/Hide/modal cancellation does not cancel an eligible parent's gap read.
Hidden/offline work defers while keeping the required barrier latched; ordinary
eligible pageshow/online required refresh closes it later. Disposal or a full parent
replacement fences retired work from synchronizing or satisfying a successor. Failure,
cached reads and error dismissal cannot certify the gap. Every new-stream invalidation
or loss hard-revokes delivery; it is never guessed to be an own completion event.

Publication requires the returned value and live original owner, current key/
identity/manager/generation/member, exact fresh accepted Done for the same Claim/
Pass/requester, unchanged relevant history, the same Secret's Core-ready Recover
instruction, satisfied target and current HTTP lease/ready epoch. The helper captures
the new render fence, decodes and delivers synchronously once, without another await
or SDK action. Only true delivery consumes that exact unread Claim. The pure port
returns an opaque finished-owner result rather than another plaintext copy. Missing,
forged or reused owners cannot deliver. Isolated adapter mode retains its old strict
epoch fence; absence of coordination is never a fallback after a failed handoff.

After delivery the capsule and temporary listeners are removed. Persistent parent
`onUnavailable` ownership remains independent of the temporary lease listener:
current EOF, transport/auth failure or missing body conceals held UI and raises the
required-sync barrier, including after delivery. Reconnect/bootstrap readiness does
not restore a value or repeat Show/Recover/auth/completion. Normal future invalidation
masks normally. JS string physical zeroization or GC timing is not claimed.
